# 화면정의서 대응

첨부 문서는 제품 요구사항 참고자료로 사용했습니다. 문서의 카카오·Apple 인증 및 REST 서버 설계보다 사용자의 **Firebase 사용 / 카카오·Apple 미구현** 요청을 우선했습니다. API는 Firebase 인증 컨텍스트를 받는 `asia-northeast3/api` callable Function으로 대체했습니다.

## 운영 전 확인할 차이점과 제한

- 실제 Firebase 프로젝트 설정, OAuth SHA 인증서 등록, 서버 배포, 실제 기기의 Google·FCM 검증은 프로젝트 소유자가 연결 후 진행해야 합니다.
- 이용약관은 개발용 안내 요약입니다. 실제 공개 전 운영자의 정식 약관·개인정보처리방침·보관 정책과 문의처를 제공해야 합니다.
- 비밀번호 재설정 토큰의 만료 시간과 전 세션 폐기는 Firebase Authentication의 정책을 따릅니다. 문서의 사용자 정의 30분 토큰 계약을 별도로 구현하지 않았습니다. 기본 메일은 Firebase의 HTTPS 웹 액션 핸들러에서 열립니다. 앱으로 바로 여는 검증된 HTTPS App Links는 실제 소유 도메인과 `assetlinks.json` 구성이 필요하므로 아직 등록하지 않았습니다.
- 일정은 월·최애별로 공개 캐시를 보관하고 조회 실패 시 오류와 마지막 갱신 시각을 함께 표시합니다. 공개 라운지 목록은 차단 상태가 바뀔 수 있어 영속 캐시를 사용하지 않습니다. 개인 기록도 공개 캐시에 넣지 않습니다.
- 초안은 앱 내부 SharedPreferences에 계정별 텍스트로 보관하며 사진·비밀번호는 보관하지 않습니다. 프로필 수정은 메모리에서 유지되며 이탈 확인을 제공합니다. 로그아웃 시 개인 초안은 제거됩니다.
- 댓글·목록은 cursor로 페이지를 추가 조회합니다. 읽지 않은 수는 현재 불러온 알림 페이지 기준입니다. 별도 전체 unread 집계는 아직 없습니다.
- 기능별 동시 수정은 expectedVersion으로 거부하며 작성 입력을 유지합니다. 충돌 후 사용자가 조회·확인하여 재시도해야 합니다.
- 요청 키는 사용자·작업별로 신규 문서 ID를 결정합니다. 같은 키로 여러 번 눌러도 한 번만 생성됩니다. 요청 문서 TTL 배포 정책은 별도로 설정할 수 있으며 현재 키 재사용 방지는 24시간보다 길게 유지됩니다.
- 일정 예약·알림은 DB outbox와 스케줄 작업으로 처리합니다. Emulator는 Scheduler를 자동 실행하지 않으며 실제 Cloud Scheduler / FCM 전달은 배포 후 검증 대상입니다.
- 같은 상세 화면을 보고 있는 동안 FCM 팝업을 억제하는 foreground 화면 연동은 아직 없습니다. FCM 수신 시 계정·대상 상태를 재검사하고 클릭하면 알림함에서 소유권을 확인한 상세로 진입합니다. 로그아웃 시 표시된 알림을 제거합니다.
- 운영 화면은 포함하지 않습니다. 관리자 claim을 가진 계정만 callable의 `adminSchedule`, `adminReports`, `adminReviewReport`를 사용할 수 있습니다. 고객 가입으로 관리자 권한을 부여할 수 없습니다.
- 서버 worker의 전체 reminders / orphan 파일 순회는 소규모 포트폴리오용 구현입니다. 대규모 운영에서는 개별 예약 큐·배치 페이지·오브젝트 수명 정책으로 확장해야 합니다.
- 5분 서명 미디어 URL은 발급 시 소유권·숨김·차단을 확인합니다. 이미 발급된 URL은 만료 전까지 유효할 수 있습니다. Emulator는 다운로드 토큰을 발급하지 않고 callable 응답의 data URI를 사용합니다.

배포된 운영 서비스나 전체 화면정의서의 최종 검수 완료로 해석하면 안 됩니다. 빌드·테스트 결과는 작업 완료 보고의 실제 실행 결과를 기준으로 합니다.
